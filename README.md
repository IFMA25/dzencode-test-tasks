# Orders & Products

SPA-приложение тестовое задание для компании DzenCode.

**Демо:** http://209.38.234.168

Приложение состоит из двух частей: клиента на Vue 3 и REST-сервера на Express с Socket.io. Данные хранятся в памяти сервера (mock-данные), база не используется.

## Обязательные инструменты

- **Vue.js (v3)** — Vue 3.5, Composition API.
- **Управление глобальным состоянием** — Pinia (актуальная рекомендация команды Vue для Vue 3).
- **Компонентный подход** — разделение на слои `app` / `pages` / `widgets` / `features` / `shared`.
- **Роутинг** — Vue Router 4, включая вложенные роуты и query-параметры.
- **Анимации при переходах** — `animate.css` для переходов между роутами, появления панели Групп и модальных окон; CSS-переходы для сворачивания таблицы и сайдбара.
- **ES6+** — стрелочные функции, spread, шаблонные строки, деструктуризация, опциональная цепочка, оператор нулевого слияния.
- **CSS Architecture** — БЭМ и scoped-стили в каждом компоненте.
- **CSS Frameworks** — Bootstrap 5 (утилиты, сетка, компоненты) и Bootstrap Icons.
- **Linters and Formatters** — ESLint с плагинами Vue, TypeScript, import и @stylistic, плюс Prettier.
- **REST** — Express с Socket.io.
- **Git** — feature-branch workflow, отдельная ветка на задачу, вливание в `main` через PR.
- **WebSocket** — Socket.io, счётчик активных сессий в реальном времени.
- **Docker** — два образа (Express и nginx со статикой) и `docker-compose.yml`, поднимающий приложение одной командой.
- **Хостинг / VDS** — приложение развёрнуто на VDS (DigitalOcean, Ubuntu 24.04) тем же `docker compose`.

## Дополнительно из уровня Junior+

- **TypeScript** — весь фронтенд на TS, проверка типов через `vue-tsc`.
- **i18n** — `vue-i18n`, русская и английская локали, автоопределение языка браузера с фолбеком на английский.
- **Web Storage** — в `localStorage` сохраняются выбранный язык и фильтр по типу продуктов.
- **Lazy Loading** — все 8 роутов подключаются динамическим `import()`: код страницы скачивается при первом переходе на неё.
- **Charts** — страница аналитики: линейная, столбчатая и кольцевая диаграммы на ECharts.

## Стек

**Frontend:** Vue 3, TypeScript, Vue Router, Pinia, Bootstrap 5, SCSS, vue-i18n, ECharts (`vue-echarts`), axios, Socket.io-client, vueuse/core, animate.css, vue-multiselect, vue-sonner, Vite

**Backend:** Node.js, Express, Socket.io, CORS

**Инструменты:** ESLint, Prettier, husky, pnpm

## Запуск

### Через Docker

```bash
docker compose up -d --build
```

Приложение на `http://localhost:8080`, остановить — `docker compose down`.

- **Два контейнера** — Express с API и nginx со статикой фронтенда.
- **Наружу открыт только фронтенд** — бэкенд доступен по имени `backend` соседнему контейнеру, но не из браузера. Все запросы идут на один адрес, nginx проксирует `/api` и `/socket.io` в Express.
- **SPA-фолбек** — nginx отдаёт `index.html` на любой роут, поэтому перезагрузка страницы не даёт 404.
- **Порт** — меняется переменной `FRONTEND_PORT`, на сервере запускается с `FRONTEND_PORT=80`.

### Локально

Нужны Node.js 18+ и pnpm 10+.

```bash
pnpm install
pnpm dev
```

Фронтенд на `http://localhost:3000`, бэкенд на `http://localhost:4000`.

- **Одна команда на две части** — проект собран как pnpm workspace.
- **Прокси** — `/api` и `/socket.io` проксирует dev-сервер Vite, адрес бэкенда в коде не зашит.
- **Переменные окружения** — не обязательны, `VITE_API_URL` по умолчанию `/api`. Пример — `frontend/.env.example`.

## Архитектура

Feature-based структура. Зависимости идут сверху вниз: нижние слои не знают о верхних.

```
src/
├── app/        конфигурация приложения: роутер, layout, стили, точка входа
├── pages/      страницы-роуты, тонкие обёртки над фичами
├── widgets/    постоянные блоки интерфейса: TopMenu, Sidebar
├── features/   бизнес-логика: orders, products, groups, search, charts, ...
├── shared/     переиспользуемое: ui-компоненты, api-клиент, утилиты, типы, i18n
└── stores/     глобальные Pinia-сторы
```

## API

Сервер поднимается на `http://localhost:4000`, все эндпоинты под префиксом `/api`.

| Метод    | Путь              | Назначение                                                                      |
| -------- | ----------------- | ------------------------------------------------------------------------------- |
| `GET`    | `/orders`         | Список приходов с вложенными продуктами. Параметр `search` — фильтр по названию |
| `DELETE` | `/orders/:id`     | Удалить приход                                                                  |
| `GET`    | `/products`       | Список продуктов. Параметры `type`, `order`, `search`                           |
| `GET`    | `/products/types` | Список типов продуктов для фильтра                                              |
| `GET`    | `/analytics`      | Три готовых набора данных для диаграмм                                          |

Через Socket.io сервер рассылает событие `sessions:count` при каждом подключении и отключении клиента.

## TopMenu

Шапка приложения адаптивна и корректно отображается на разной ширине экрана в соотвестии с брекпоинтами Bootstrap.

**Состоит из:**

- **Логотип** — иконка + название проекта, при клике на логотип происходит переход на главную страницу.
- **Поиск** — контекстный поиск по данным текущей страницы, подробнее в разделе Search.
- **Активные сессии** — счётчик пользователей приложения онлайн в реальном времени реализован с помощью Socket.io: сервер считает текущее число подключений и рассылает всем клиентам событие при каждом подключении/отключении.
- **Дата и время** — текущие день недели, дата и время, обновляются реактивно (`useNow` из `@vueuse/core`). День недели и месяц форматируются через `Intl.DateTimeFormat` с учётом текущего языка приложения.
- **Переключатель языка** — селект с списков доступных языков, меняет локаль приложения. Текущая локаль пользователя подхватывается автоматически. Локаль сохраняеться в локальную pinia store и при обновлении страницы локаль не сбрасывается, сохраняется в localStorage. Если локаль пользователя не поддерживаеться, то по умолчанию устанавливается английский язык.

## Sidebar

Sidebar строится динамически на основе роутов приложения и адаптивно реагирует на ширину экрана.

**Состоит из:**

- **Навигация** — пункты меню формируются автоматически из зарегистрированных роутов.
- **Активный пункт** — у текущего роута есть визуальный индикатор: в развёрнутом состоянии подчёркивается текст, в свёрнутом (иконка без текста) — иконка перекрашивается в акцентный цвет, без анимаций подчёркивания.
- **Сворачивание/разворачивание** — вручную через кнопку-стрелку либо автоматически по ширине экрана.
- **Анимация переключения текста/иконки** — при смене состояния текст и иконка плавно сменяют друг друга.
- **Профиль** — аватар пользователя и кнопка-шестерёнка поверх него, по клику открывающая страницу настроек профиля (пока с заглушкой).

## Orders (Приходы)

Список приходов реализован на базе mock-данных. Каждый элемент отображает название прихода, количество продуктов в приходе, даты создания прихода в двух форматах, сумма прихода, равная сумме цен продуктов в двух валютах и кнопку удаления прихода.

**Состоит из:**

- **Таблица** — компонент на CSS Grid, это позволяет делать карточные строки с тенью/скруглением.
- **Данные** — загружаются с бэкенда через Pinia store (`useOrdersStore`), с состояниями загрузки (лоадер) и ошибки (сообщение внутри таблицы вместо списка).
- **Удаление** — кнопка на строке открывает модальное окно подтверждения с превью удаляемого прихода. Во время запроса на кнопке подтверждения показывается лоадер, обе кнопки блокируются. При успехе список приходов перезапрашивается заново, при ошибке — всплывающее уведомление (`vue-sonner`), модальное окно при этом не закрывается.

## Groups (Группы)

Клик по приходу в таблице Orders открывает рядом со списком роут `groups/:id` — компактную панель с продуктами выбранного прихода. Список приходов при этом остаётся смонтированным, скрывается только часть его колонок.

**Состоит из:**

- **Роутинг** — `groups` зарегистрирован как дочерний роут `orders`, а не отдельная страница. Это позволяет рендерить панель продуктов рядом со списком приходов через вложенный `router-view`, без размонтирования Orders.
- **Данные** — продукты запрашиваются отдельным запросом к бэкенду (`GET /products?order=:id`) при открытии панели, а не берутся из уже загрученного в `useOrdersStore` прихода. Бэкенд — источник истины: если продукты изменились где-то ещё (пока пользователь смотрит список приходов), панель Groups всегда покажет актуальные данные, а не то, что осталось закешированным в сторе с момента загрузки списка приходов.
- **Пустое состояние** — если открыть вкладку "Группы" напрямую (не кликнув по конкретному приходу), `id` прихода отсутствует, соответственно нет и прихода, для которого нужно запрашивать продукты - панель показывает заглушку "Выберите приход" вместо пустой таблицы.

## Products (Продукты)

Список продуктов реализован на базе mock-данных. Каждый элемент отображает индикатор состояния (новый/Б/У), фото, название продукта, тип, состояние, даты гарантии в двух форматах, цену в двух валютах и название прихода, к которому относится продукт.

**Состоит из:**

- **Таблица** — тот же переиспользуемый компонент `VGridTable` на CSS Grid, что и в Orders, вынесенный в `shared/ui`.
- **Данные** — загружаются с бэкенда через Pinia store, с состояниями загрузки (лоадер) и ошибки (сообщение внутри таблицы вместо списка).
- **Фильтр по типу** — селект в toolbar-слоте таблицы, фильтрация происходит на бэкенде. Опция "Все типы" выбрана по умолчанию и корректно переводится при смене локали. Выбранный фильтр сохраняется в `localStorage` и восстанавливается при перезагрузке страницы.
- **Цена** — суммы округляются до 2 знаков после запятой; если дробная часть нулевая `.00`, она не отображается.

## Search (Поиск)

Поле поиска в TopMenu одно на всё приложение, но ищет по данным той страницы, на которой сейчас находится пользователь: на Приходах — по названию прихода, на Продуктах — по названию продукта. Фильтрация выполняется на бэкенде (`?search=`), регистр не учитывается.

**Состоит из:**

- **Фича `features/search`** — отдельная фича `SearchFeature`.
- **Доступность по роутам** — поиск включается через `meta.search` в конфигурации роута, так же как из `meta` строится навигация в сайдбаре. Там, где искать нечего (Аналитика, Настройки, Пользователи, Профиль), поле остаётся видимым, но не активным. Новая страница без явного `meta.search: true` получит выключенный поиск.
- **Запрос в URL** — введённое значение попадает в query-параметр `?search=`. Благодаря этому поиск переживает перезагрузку страницы, работает кнопка «Назад», а ссылкой с результатами можно поделиться.
- **URL как источник истины** — страницы Приходов и Продуктов сами следят за `route.query.search` и перезапрашивают данные при любом его изменении.
- **Дебаунс** — запрос уходит через 400 мс после последнего нажатия клавиши (`useDebounceFn`), поле при этом обновляется мгновенно.
- **Отмена запросов** — перед каждым новым запросом предыдущий незавершённый отменяется через `AbortController`. Отменённый запрос не показывается пользователю как ошибка.
- **Сохранение при переходе Приходы ↔ Группы** — навигация внутри этого раздела передаёт текущий `query`, поэтому найденный список не сбрасывается при открытии панели продуктов. При переходе в другой раздел параметр не передаётся и поиск очищается.
- **Пустое состояние** — если поиск ничего не нашёл, вместо «Добавьте … для отображения» показывается «По вашему запросу ничего не найдено».

## Analytics (Аналитика)

Страница с тремя диаграммами (`vue-echarts`). Сверху — линейный график на всю ширину, снизу в одной строке гистограмма (65%) и кольцевая диаграмма (35%), при уменьшении экрана графики перестраиваются в столбец.

**Состоит из:**

- **Диаграммы:**
  - _Line_ — количество приходов по годам.
  - _Bar_ — количество продуктов в каждом приходе; по оси X id приходов.
  - _Pie_ — распределение типов продуктов в процентах; название и процент показываются в центре кольца при наведении.
- **Данные** — один запрос `GET /analytics`, который возвращает сразу три готовых к отрисовке набора. Агрегация делается на бэкенде и пересчитывается на каждый запрос.
- **Загрузка данных** — композабл `useAnalytics` внутри фичи. Данные нужны только на этой странице и не используются другими фичами. Композабл вызывается один раз в `AnalyticsFeature`, результат передаётся диаграммам пропсами - сами диаграммы остаются презентационными и ничего не запрашивают.
- **Общая карточка** — компонент `ChartCard` инкапсулирует каркас (рамку, заголовок, фиксированную минимальную высоту) и все три состояния: загрузка, ошибка, пустые данные. Каждая диаграмма описывает только то, что у неё уникально - объект `option` и форму скелетона.
- **Скелетоны** — вместо спиннера, так как подсказывают форму будущего контента: полосы для линейного графика, вертикальные столбцы для гистограммы, круг для кольцевой. Реализованы на плейсхолдерах Bootstrap (`placeholder` + `placeholder-glow`).
- **Палитра** — вынесена в `features/charts/variables/chartColors.ts`, так как ECharts рисует на canvas и не может читать CSS-переменные.
- **Адаптивность** — все диаграммы с `autoresize`; ниже 992px сетка перестраивается в одну колонку.
